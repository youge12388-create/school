# 宝塔一键发布（云端构建）操作速查

> 供日常发布与故障排查使用。本方案下**服务器不执行构建**：推送代码后，GitHub Actions 在云端自动完成 `npm ci + next build` 并把产物发布为 Release；服务器只做「拉代码 → 下载产物 → 换包 → 重启 → 健康检查」。

## 一、日常发布（宝塔终端，root 身份）

```bash
cd /opt/school-opt
git checkout master && git pull --ff-only
bash scripts/deploy.sh --check   # 可选：预检（控制器/分支/工作区）
bash scripts/deploy.sh           # 一键发布
```

**发布前注意**：确认 GitHub Actions 已为当前 master 提交产出 Release（推送后约 3–5 分钟）。查看方式：仓库页 → Actions 标签页（绿色 success）；或 Releases 标签页有 `build-<commit>`。

**成功标志**（deploy.sh 最后一行）：

```
[school_syt deploy] Release completed successfully at commit b4c86eac
```

**验证新版**：打开 `https://check.medicalchinaway.com/login` —— 登录页右上角有「中 / EN」切换、登录后侧栏顶部 ☰ 折叠后内容区变宽，即为新版。

## 二、首次接入 / 脚本更新后的引导

如果之前手动 pull 过代码，或服务器上 deploy.sh 是旧版，先更新脚本再发布（**不要在服务器上手动跑 `npm run build`**）：

```bash
cd /opt/school-opt
git checkout master && git pull --ff-only
bash scripts/deploy.sh
```

deploy.sh 用仓库外标记 `/opt/.school_syt_release_commit` 判断"运行包是否已发布当前提交"：
- 标记与当前 commit 一致 → 提示 `nothing to do`（正常，说明已是最新）；
- 代码新、标记旧/缺失 → 自动下载当前 commit 产物并发布（引导场景，正是上面流程）。

## 三、故障排查

| 现象 | 处理 |
|---|---|
| `nothing new to release` / `Already released …` | 正常：当前版本已发布，无需操作 |
| `Standalone artifact … not available` | Actions 还没跑完或失败：去仓库 Actions 页查看，失败可点 `workflow_dispatch`（Run workflow）重跑；完成后重新执行 `bash scripts/deploy.sh`（脚本会还原 Git 并安全退出，不影响运行中服务） |
| 发布中途失败（报错即回滚） | 脚本自动 `git reset` 回旧提交并用 `.old` 还原旧运行包重启；把终端最后 10–20 行发给维护者 |
| 站点 502 / 打不开 | 最快恢复：宝塔面板 → Node 项目 `school_syt` → 点「启动」（启动不构建）；再查：`curl -sS -I https://check.medicalchinaway.com/login` 与 `curl -sS -m 5 http://127.0.0.1:3000/api/health` |
| 页面 404 | 同上两步；如进程正常仍 404，检查宝塔站点根目录/反向代理配置 |
| 想手动验证产物可下载 | `curl -sIL https://github.com/youge12388-create/school/releases/download/build-<commit>/standalone.tar.gz`（公开仓库免凭证） |

## 四、架构要点（发生了什么）

```
git push master
   ↓ 自动触发
GitHub Actions（免费，公开仓库不限分钟）
   ├ npm ci → next build → 打包 .next/standalone
   └ 发布 Release: build-<commit>/standalone.tar.gz
   ↓
宝塔 deploy.sh（/opt/school-opt，root）
   ├ git pull --ff-only（仅 master）
   ├ 下载并校验对应 commit 的 standalone 产物
   ├ 备份数据库（npm run backup）
   ├ 交换 .next/standalone（旧包暂存 .old，健康检查通过后删除）
   ├ 宝塔本地 Node 控制器重启 school_syt
   └ /api/health 进程级健康检查；失败自动回滚（git reset + .old 还原 + 重启）
```

- 关键文件：`.github/workflows/build-standalone.yml`（云端构建）、`scripts/deploy.sh`（服务器发布）。
- 服务器拓扑：`/opt/school-opt`、宝塔 Node 项目 `school_syt`、Node `/www/server/nodejs/v24.18.0/bin`、健康检查 `https://check.medicalchinaway.com/api/health`。
- 服务器内存小，**严禁在服务器上执行 `npm ci` / `npm run build`**（会整机 OOM 崩溃）——这正是采用云端构建方案的原因。
- 仓库必须保持 public（免费无限构建分钟 + 服务器免凭证下载产物）；改为 private 后需另配令牌并受 2000 分钟/月限制。

## 五、历史背景（为什么是这套）

2026-09 曾因在服务器上直接 `npm run build` 导致整机 OOM 崩溃（站点 502、发布自动回滚）。随后把发布改造为「GitHub Actions 云端构建 + 服务器只下载产物重启」，彻底规避。详见 `docs/PROJECT_STATE.md`。
